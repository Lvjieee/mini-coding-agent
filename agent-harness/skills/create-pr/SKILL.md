# create-pr

description: 为当前仓库的代码变更创建 PR/MR（读规则、验证、生成说明、授权后发布）

## 适用场景

用户要求为当前仓库的代码变更创建 PR。

## 流程

1. 读取 AGENTS.md / WORKBUDDY.md 和仓库贡献规范。
2. 检查 git status，不覆盖用户的未提交修改。
3. 阅读 diff，识别变更范围与风险。
4. 运行与改动相关的格式化、类型检查和测试。
5. 仅在验证通过后生成标题和描述，如实列出未验证项。
6. 确认用户已授权发布，再 push 并创建 PR（发布属不可撤销操作，必须经过审批门）。

## 失败分支

- 测试失败：定位原因并修复后重新验证；无法修复时停在草稿状态，如实说明。
- 没有推送权限：停在本地分支与说明文件，交接给用户。

## 完成标准

- PR 只包含本任务的变更。
- 已记录所运行的测试与结果。
- 标题、正文、Issue 关联符合团队规范。
